# TitanX 项目安全原则

版本：2026-09-10。范围：模型调用、工具执行、审批恢复、上下文、网关和执行环境。

以下是 TitanX 的工程要求，结合[现有安全设计](../model-tool-loop-security-design.md)
整理；`TXS` 编号是项目自定义编号。括号中的 ASI 编号是我们与
[OWASP Agentic Top 10 2026](references/README.md) 的风险关联，不是官方认证或覆盖结论。
现有实现的差距单独记录在[落地清单](ADOPTION.md)。

## TXS-01：模型提出操作，宿主决定权限

模型输出的工具名、参数和解释均是待验证的提案。注册目录、身份、策略、批准记录和
执行权限由宿主维护。用户任务表达目标，但不能单凭自然语言更改服务端权限。
模型、网页或工具结果中的“已批准”文字不得改变授权状态。

确定性权限检查放在实际派发入口；提示词、注入扫描和模型自检作为辅助控制。
自定义 adapter 和同进程插件属于宿主信任的程序代码；运行不信任代码需要独立隔离。
关联：ASI01、ASI03。

## TXS-02：按操作与资源授予最小能力

工具注册不等于允许访问全部资源。宿主须明确谁能对哪些文件、记录、接口执行哪些动作，
并限制数据量和访问范围。优先提供职责明确的窄工具，只开放任务实际需要的能力。
权限不明确或执行环境不能落实必要限制时，不派发操作。

例：读取项目文件的授权仅覆盖指定工作区与读取动作，不自动包含发送文件内容的权限。
关联：ASI02、ASI03。

## TXS-03：需要审批的操作必须精确绑定

批准覆盖审批界面展示的具体操作。宿主生成操作标识，绑定身份、会话、工具契约、
规范化参数、资源范围及策略版本；批准具有有效期、消费和撤销状态。
执行前复验，并原子地占用执行记录。审批界面展示实际执行描述及预期影响，不能只展示
模型生成的理由。参数或目标变化后，重新按当前策略判定。

已有窄范围宿主策略可直接覆盖常规操作；需要人类审批的高影响操作才暂停等待。
关联：ASI02、ASI03、ASI09。

## TXS-04：身份与会话范围来自认证上下文

用户、租户和凭证由宿主认证结果确定，不能从模型参数或未经认证的请求字段接受。
访问会话、批准、执行记录、归档及回查时，都检查当前主体的资源权限。
session ID 是资源标识，不是访问凭证。

多租户部署须由网关和存储共同落实主体隔离；单个共享 API key 不代表完成租户授权。
关联：ASI03、ASI06。

## TXS-05：验证完整参数并维护可信工具契约

在执行边界验证工具契约、参数 schema、嵌套结构、类型和大小限制，明确多余字段的处理。
执行使用验证和授权时的同一份参数快照。外部工具声明的名称、描述、schema、版本和
来源变化须重新准入；工具自己提供的“安全”标签不能降低宿主要求。

MCP 连接应限定服务器和工具，按部署需要固定可信契约。首次使用建立的基线只能发现
后续变化，不能证明首次连接的内容可信。插件代码和依赖的准入独立于工具文本检查。
关联：ASI02、ASI04。

## TXS-06：限制由执行环境真正落实

路径、挂载、网络、凭证、进程和资源限制必须由实际后端或下游服务执行。
路由选择须满足操作声明的最低隔离要求；所需后端不可用时，不静默降低要求。
字符串扫描、风险标签或后端名称不能代替隔离证据。

新增自定义 ToolRuntime 时明确它在哪执行、继承什么权限，以及哪些限制需要宿主接入。
关联：ASI02、ASI05。

## TXS-07：上下文与记忆始终是数据

工具返回、检索内容、外部文档和摘要保留来源，不能升级为系统策略或批准记录。
TaskState 与消息历史分离；授权记录不从摘要重建。压缩保留当前任务约束与消息协议，
丢失的信息可通过受权限约束的归档回查。

扫描和包装有助于识别不可信内容，但扫描通过不代表可信。摘要错误不能扩大执行权限。
关联：ASI01、ASI06。

## TXS-08：凭证留在执行侧，外发单独授权

凭证按身份和工具范围注入执行侧，避免进入模型上下文、摘要、事件和普通日志。
读取权限与对外发送权限分开；外发检查目标、方法、路径、数据类别及授权范围。

网络检查接口须接入实际出口，或由沙箱网络控制强制执行；绕过统一客户端的访问不能
被描述为已受该接口保护。日志脱敏和输出清洗失败时也应避免泄露原始敏感内容。
关联：ASI02、ASI03、ASI06。

## TXS-09：恢复保留授权，重试尊重副作用

审批恢复先处理未完成工具批次，再进入下一轮模型调用。拒绝项产生对应工具结果，
已完成项不因后续处理失败重新派发。恢复时复验尚未执行的操作及其授权。

外部结果不确定时保留 `unknown` 状态。非幂等操作只有在下游提供可靠幂等机制或能确认
安全重试时才自动重发；重试约束要覆盖运行时和后端包装层。跨进程恢复依赖执行账本，
不能从模型消息推断外部动作是否发生。取消也不代表已经回滚外部副作用。
关联：ASI02、ASI08。

## TXS-10：限制自主运行的范围与消耗

明确模型轮数、工具调用量、总时长、重试次数、并发、输出大小及成本边界。
达到限制后停止或返回可处理状态；恢复不能意外重置同一操作的受限消耗。
熔断后的恢复采用受控探测，避免永久跳过后端或同时放入大量探测。

宿主具备取消和撤销后续执行权限的入口。停止原因可观察，不能将超限伪装为任务完成。
关联：ASI08、ASI10。

## TXS-11：审计反映实际执行状态

决策与执行事件关联到宿主操作标识、身份、会话、工具契约、策略版本、批准和结果状态。
“已批准”“已派发”“成功”“失败”“结果不确定”分别记录。日志只保留必要数据。

要求执行前可靠落账的场景，须取得持久化确认后再派发；后台排队写入不能替代确认。
审计失败不能触发已完成动作重放。抗篡改和跨进程恢复需要各自的存储与验证机制。
关联：ASI08、ASI09、ASI10。

## TXS-12：委派不会自动继承全部权限

未来接入多 Agent 或远程任务时，传递可验证的身份、任务范围、权限上限、期限与关联标识。
接收方独立认证和授权，限制重复提交与跨任务访问。子任务只获得所需能力，返回内容
按外部数据处理；不能仅因为来自另一个 Agent 就直接执行其指令或信任其批准声明。

这条是扩展约束，不表示当前代码已提供完整的多 Agent 授权协议。
关联：ASI03、ASI07、ASI10。
